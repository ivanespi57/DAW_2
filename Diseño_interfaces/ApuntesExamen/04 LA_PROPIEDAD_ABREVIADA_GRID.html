LA PROPIEDAD ABREVIADA GRID

Para aquellos que les gusta mantener sus hojas de estilo tan eficientes como sea posible, el módulo Grid Layout proporciona la propiedad abreviada grid. La sintaxis difiere según se use para grids explícitas o implícitas.

grid Abreviada para Grids Explícitas

Ahora que has sido introducido a todas las formas de configurar una grid explícita, incluyendo valores de tamaño de pista y asignación de nombres de línea y área, es momento de juntarlos todos en la propiedad abreviada grid. Puedes usar esta propiedad para establecer valores para grid-template-rows, grid-template-columns, y grid-template-areas con una regla de estilo. Ten en cuenta que cualquier propiedad que no uses se restablecerá a sus valores por defecto, como es el caso para todas las propiedades abreviadas.

grid

Valores: none | info de fila / info de columna
Por defecto: none
Se aplica a: Contenedores de grid
Hereda: No

En grid, los valores de fila y columna se separan por una barra, con los valores de fila apareciendo primero. Este ejemplo es una vista muy simplificada de la estructura de valor:

grid: rows / columns

Aquí está la declaración abreviada para nuestra grid explícita de ejemplo con solo información de pista de fila y columna. He omitido nombres de línea y área por ahora porque es más fácil entender la sintaxis grid sin ellos (ver Nota); añadiré los nombres de vuelta en un paso a la vez:

#layout {
    display: grid;
    grid: 100px 400px 100px / 200px 1fr 200px;
}

Porque los valores de pista para grid tienden a volverse bastante largos, es común mover la información de pista a sus propias líneas para mayor claridad. Verás por qué esto es útil pronto. Aquí está la misma declaración grid con valores de fila y columna apilados:

#layout {
    display: grid;
    grid:
        100px 400px 100px
        / 200px 1fr 200px;
}

NOTA
No todas las grids usan líneas nombradas y áreas, así que son opcionales, por supuesto.

Para incluir nombres de línea personalizados, añade los nombres entre corchetes ([]) junto a sus pistas respectivas, como hicimos en los ejemplos de líneas nombradas anteriormente en este capítulo. Añadamos los nombres de línea de columna que establecimos de vuelta en la lista de pistas de columna:

#layout {
    display: grid;
    grid:
        100px 400px 100px
        /[ads] 200px [main] 1fr [links] 200px;
}

Incluir nombres de área se ve un poco complicado al principio, pero si recuerdas que asignas nombres de celda fila por fila, tiene sentido que aparezcan con la otra información de fila, antes de la barra. La sintaxis completa para valores de fila va en este orden:

[start line name] "area names" <track size> [end line name]

Repite esta estructura para cada fila en la grid, simplemente listándolas una tras otra sin ningún carácter especial separando filas. Puedes ver cómo apilar valores como hemos hecho en el siguiente ejemplo ayuda a mantener cada fila distinta. Cuando las filas están terminadas, añade una barra, y lista la información de pista de columna después de ella. Aquí está la declaración completa para nuestra grid de ejemplo usando la abreviada grid:

#layout {
    display: grid;
    grid:
        [header-start] "header header header" 100px [header-end]
        [content-start] "ads    main   links" 400px
        [footer-start] "footer footer footer" 100px [footer-end]
        /[ads] 200px [main] 1fr [links] 200px;
}

Esto se expande a lo siguiente:

#layout {
    display: grid;
    grid-template-rows: [header-start] 100px [header-end content-start]
    400px [footer-start] 100px[footer-end];
    grid-template-columns: [ads] 200px [main] 1fr [links] 200px;
    grid-template-areas:
        "header header header"
        "ads    main   links"
        "footer footer footer"
}

Con el potencial de que los valores se vuelvan tan elaborados y complicados, es discutible si la abreviada grid es un verdadero atajo (ver Nota).

NOTA
Los expertos en Grid Layout con los que he hablado no tienden a usar grid-template excepto para las estructuras de grid más simples. El código se vuelve excesivamente complejo, y un pequeño desliz puede hacer que toda la grid se desmorone. Para estructuras de grid complicadas, probablemente querrás ceñirte a propiedades separadas para definir filas, columnas y áreas.

También hay una propiedad abreviada grid-template que funciona exactamente como grid, pero puede usarse solo con grids explícitamente definidas, como sustituto de grid-template-rows / grid-template-columns. La especificación Grid Layout recomienda que uses la abreviada grid en lugar de grid-template a menos que específicamente quieras el comportamiento en cascada de grid-template.

grid Abreviada para Grids Implícitas

La propiedad abreviada grid también puede usarse con propiedades de grid implícita. Añadir el valor de palabra clave auto-flow a la información de pista de fila o columna indica que las pistas en ese eje deben generarse automáticamente en la dimensión proporcionada.

Digamos que queremos establecer columnas explícitamente, pero dejar que las filas se generen automáticamente según sea necesario. La grid implícita que hicimos al comienzo de este capítulo podría escribirse con la abreviada grid así:

#layout {
    display: grid;
    grid: auto-flow 4em / 300px 300px 300px;
}

Recuerda que la sintaxis abreviada grid lista la información de fila primero, luego una barra, luego la información de columna. Aquí, la regla dice crear filas automáticamente que son de 4em de alto y crear tres columnas de 300px. Cuando auto-flow se aplica a las filas, la propiedad grid-auto-flow se establece a row.

Cuando auto-flow se aplica a los valores de columna, grid-auto-flow se establece a column. Así es como el ejemplo de columna implícita que escribiste en el último paso del EJERCICIO 13-1 podría escribirse con grid:

dl {
    display: grid;
    grid: repeat(3,3em 1fr) / autoflow 6em;
    gap: .5em;
}

Es importante tener en cuenta que porque grid es una propiedad abreviada, cualquier valor omitido se restablecerá a su valor por defecto. Por lo tanto, si también has usado grid para configurar filas y columnas explícitas, esas se perderán si una abreviada grid con instrucciones de grid implícita aparece más tarde en la hoja de estilos.

Bueno, eso fue una larga explicación para una propiedad abreviada. Ahora conoces todos los detalles de configurar grids y colocar elementos en ellas. En la siguiente sección, conocerás las propiedades para controlar el espaciado y alineación de celdas de grid y elementos dentro de ellas. Pero primero, echa un vistazo a la barra lateral “Grid Item Shuffle” para ver cómo las propiedades order y z-index que aprendiste en capítulos anteriores se aplican también a Grid Layout.

Grid Item Shuffle

Hasta ahora, has visto elementos de grid fluyendo hacia una grid secuencialmente o siendo colocados en sus propias pequeñas áreas explícitamente. Hay algunas propiedades que pueden ser útiles para ajustar la posición de elementos de grid.

Cambiando el orden
Como con elementos flex, puedes aplicar la propiedad order a un elemento de grid para cambiar el orden en que aparece cuando se renderiza. Ten en cuenta que la propiedad order no cambia el orden en que los elementos son leídos por un lector de pantalla, sin embargo, así que úsala con cuidado. Consulta la sección “Cambiando el Orden de Elementos Flex” en el Capítulo 17 para más información sobre cómo usar order. Los mismos principios se aplican con elementos de grid.

Orden de apilamiento
Es posible posicionar elementos en una grid de manera que causen superposición. Cuando más de un elemento se asigna a un área de grid, los elementos que aparecen más tarde en el código fuente se renderizan encima de elementos anteriores en el código fuente, pero puedes cambiar el orden de apilamiento usando la propiedad z-index. Asignar un valor z-index más alto a elementos anteriores hace que se rendericen por encima de elementos que aparecen más tarde. Consulta la sección “Orden de Apilamiento” en el Capítulo 16, Flotación y Posicionamiento, para detalles sobre usar z-index.

ALINEACIÓN Y ESPACIADO DE GRID

Las grids usan la colección de propiedades de alineación y espaciado que “controlan la alineación de cajas dentro de otras cajas”, como se define en el Módulo de Alineación de Cajas CSS Nivel 3 (w3.org/TR/css-align-3/). Las propiedades fueron originalmente extraídas de la especificación Flexbox, por lo que deberían parecer familiares. Las propiedades de alineación de cajas fueron diseñadas para aplicarse a los modos de visualización de bloque y tabla también; sin embargo, no hay soporte de navegador para esas aplicaciones al momento de escribir esto. Con todas las propiedades de alineación documentadas en una especificación central, hay menos posibilidad de conflictos entre los varios modos de visualización.

Las propiedades de alineación de cajas caen en tres categorías, para:

• Alineación y espaciado de cajas dentro de sus contenedores (es decir, pistas dentro de un contenedor de grid)

• Alineación de elementos dentro de sus cajas (es decir, elementos dentro de sus celdas de grid o áreas)

• Espaciado añadido entre pistas (las propiedades gap)

Las propiedades de alineación usan términos consistentes para la alineación en cada eje. Las propiedades que posicionan pistas o elementos a lo largo del eje de bloque (verticalmente en nuestros ejemplos) comienzan con align-. Las propiedades que alinean pistas o elementos a lo largo del eje en línea (horizontalmente) comienzan con justify-. Mantener estos prefijos en mente puede hacer que el conjunto de propiedades de alineación sea más fácil de recordar.

Vamos a comenzar nuestra lección de alineación moviendo grupos de pistas de fila y/o columna dentro de su contenedor de grid.

Las propiedades de alineación del eje de bloque comienzan con align-.
Las propiedades de alineación del eje en línea comienzan con justify-.

Alineando Pistas Dentro de un Contenedor de Grid

Puede haber casos en los que las pistas de tu grid no llenen toda el área de su contenedor de grid—por ejemplo, si has especificado tres columnas de 200 píxeles en una grid que tiene 800 píxeles de ancho (ver Nota). Puedes decidir cómo el navegador debe manejar el espacio sobrante dentro del contenedor usando las propiedades justify-content (eje horizontal/en línea) y align-content (eje vertical/de bloque). El sufijo -content es la convención del módulo de Alineación de Cajas para indicar la alineación de cajas de contenido dentro de sus contenedores.

justify-content

Valores: start | end | left | right | center | stretch | space-around | space-between | space-evenly
Por defecto: start
Se aplica a: Contenedores de grid
Hereda: No

align-content

Valores: start | end | left | right | center | stretch | space-around | space-between | space-evenly
Por defecto: start
Se aplica a: Contenedores de grid
Hereda: No

NOTA
Algunos valores de pista, como fr y ciertos valores basados en contenido, hacen que las pistas llenen el espacio disponible en la grid, por lo que las propiedades de alineación no tendrán efecto.

NOTA
La palabra clave stretch solo funciona cuando el ancho o altura de la pista se establece a auto.

mueven todas las pistas dentro del contenedor poniendo el espacio extra después, antes, o igualmente en ambos lados de ellas, respectivamente. Las palabras clave space-around y space-between distribuyen espacio alrededor de las pistas, como se discutió en el Capítulo 17. La palabra clave space-evenly añade una cantidad igual de espacio entre elementos y al inicio y final de cada pista.

Alineando Elementos Dentro de Sus Áreas de Grid

De manera similar, puedes alinear elementos dentro de sus áreas de grid cuando hay espacio sobrante. Comenzaremos mirando las propiedades para ajustar la alineación de elementos individuales y luego seguiremos con propiedades que cambian la alineación de todas las áreas de grid a la vez.

Alineando elementos individuales

justify-self

Valores: start | end | center | left | right | self-start | self-end | stretch | normal | auto
Por defecto: auto (mira el valor para justify-items, que por defecto es normal)
Se aplica a: Elementos de grid
Hereda: No

align-self

Valores: start | end | center | left | right | self-start | self-end | stretch | normal | auto
Por defecto: auto (mira el valor para align-items)
Se aplica a: Elementos de grid
Hereda: No

Cuando un elemento de grid no llena toda su área de grid, puedes especificar cómo te gustaría que se alineara dentro de ese espacio. Como esperarías, la propiedad justify-self se alinea en el eje en línea y align-self especifica alineación en el eje de bloque. Estas propiedades se aplican al elemento de grid, lo que tiene sentido porque quieres que ese elemento se alinee a sí mismo.

La FIGURA 11 muestra los efectos de cada valor de palabra clave. Para elementos con su tamaño establecido a auto (o en otras palabras, no establecido explícitamente con propiedades width y height), el valor por defecto es stretch. Esto es lo que has visto en todos los ejemplos de grid anteriores. Si el elemento de grid tiene un ancho y altura especificados, esas dimensiones se preservan y el valor por defecto es start.

FIGURA 11. Valores para justify-self y align-self para alinear un solo elemento de grid dentro de su área de grid respectiva. Estos valores tienen el mismo uso en las propiedades justify-items y align-items que se usan para alinear todos los elementos en la grid.

NOTA
Los valores self-start y self-end miran la dirección de escritura del contenido del elemento y usan su borde de inicio o final para la alineación. Si un elemento está en árabe, su borde self-start está a la derecha, y se alineará a la derecha. Los valores start y end son absolutos y no cambiarán con el sistema de escritura, pero corresponden a start y end en idiomas de izquierda a derecha.

CONSEJO
Si quieres que un elemento de grid permanezca centrado en su área de grid, establece tanto align-self como justify-self a center.

justify-items

Valores: start | end | center | left | right | self-start | self-end | stretch | normal
Por defecto: normal (stretch para elementos no reemplazados; start para elementos reemplazados)
Se aplica a: Contenedores de grid
Hereda: No

align-items

Valores: start | end | center | left | right | self-start | self-end | stretch | normal
Por defecto: normal (stretch para elementos no reemplazados; start para elementos reemplazados)

Para alinear todos los elementos en una grid de una sola vez, usa la propiedad justify-items para alineación del eje en línea y align-items para el eje de bloque. Aplica estas propiedades al elemento contenedor de grid para que afecte a todos los elementos en la grid. Las palabras clave hacen las mismas cosas mostradas en la FIGURA 18-22, solo que sucede consistentemente a través de toda la grid. Ten en cuenta que estas configuraciones serán anuladas por las propiedades -self.

Hablando de Espaciado, ¿Qué Pasa con los Márgenes?

Puedes añadir márgenes a un elemento de grid como puedes para cualquier otro elemento. Es útil saber que el margen de la caja será anclado a la celda o área de grid, y el espacio del margen se preserva.

Puedes usar márgenes para mover el elemento alrededor en el área de grid. Por ejemplo, establecer el margen izquierdo a auto empuja el elemento a la derecha, como vimos en los ejemplos de Flexbox en el capítulo anterior. Establecer los márgenes izquierdo y derecho a auto (siempre que el elemento tenga un ancho especificado) lo centra horizontalmente. En Grid Layout, también puedes establecer los márgenes superior e inferior a auto y, siempre que haya una altura especificada, el elemento se centrará verticalmente. Por supuesto, tienes las propiedades de alineación de caja para lograr estos efectos también.

Añadiendo Espacio Entre Pistas (gap)

Para algunas grids, es agradable tener un poco de espacio para respirar entre filas o columnas (¡o ambas!) sin necesidad de configurar pistas extra solo para contener espacio. Añadir canaletas entre pistas es el trabajo de la colección de propiedades gap (ver Nota) definidas en el módulo de Alineación de Cajas. Puedes recordar que gap también puede usarse con flexboxes y diseños multicolumna.

row-gap**

column-gap
Valores: longitud (no debe ser negativa)
Por defecto: 0
Se aplica a: Contenedores de grid
Hereda: No

gap

Valores: grid-row-gap grid-column-gap
Por defecto: 0 0
Se aplica a: Contenedores de grid
Hereda: No

Has tenido la oportunidad de usar la propiedad gap en los ejercicios, así que esto debería sonar familiar. Establecer un valor de longitud para row-gap añade espacio entre las pistas de fila de la grid y column-gap añade espacio entre las pistas de columna. El efecto es como si las líneas de grid tuvieran un ancho; sin embargo, el ancho del gap se aplica solo a líneas entre pistas, no a las primeras y últimas líneas en los lados de la grid.

Puedes usar la abreviada gap para especificar anchos de gap para filas y columnas de una vez, con filas primero como es usual, separadas por un espacio de carácter. En este ejemplo, he añadido 20px de espacio entre filas y 50px de espacio entre columnas usando la abreviada gap (FIGURA 12):

#container {
    border: 2px solid gray;
    display: grid;
    grid: repeat(4, 150px) / repeat(4, 1fr);
    gap: 20px 50px;
}

NOTA
En versiones anteriores de la especificación Grid Layout, estas propiedades tenían el prefijo grid- (por ejemplo, grid-row-gap). Las versiones sin prefijo del módulo de Alineación de Cajas están bien soportadas en navegadores modernos; sin embargo, los navegadores continuarán soportando las versiones con prefijo para compatibilidad hacia atrás.

GRIDS RESPONSIVAS

Como recordatorio, el diseño web responsivo es una estrategia para crear sitios que cambian o se adaptan basándose en el tamaño del viewport. De esta manera, el mismo documento HTML puede organizarse de manera diferente según se muestre en un smartphone, tablet o pantalla grande.

Puedes tender a pensar en una grid como una estructura rígida, pero hay varios métodos para incorporar Grid Layout en diseños responsivos.

La Unidad fr

La forma más fácil de introducir algo de flexibilidad en tu grid es usar unidades fr (fraccionarias) para anchos de columna. No resolverán todos los desafíos de diseño, pero son un buen punto de partida para asegurarte de que tus pistas se encojan o crezcan para llenar el espacio disponible. Discutí las unidades fr en la sección “Especificando Valores de Tamaño de Pista” anteriormente en este capítulo, pero aquí hay un ejemplo rápido que especifica cuatro columnas que crecerán o se encogerán según el espacio lo permita, con la cuarta columna siempre cuatro veces el ancho de las otras tres:

grid-template-columns: 1fr 1fr 1fr 4fr;

minmax()

Establecer tamaños de pista con la función minmax() también introduce flexibilidad, pero permite a los autores establecer límites sobre qué tan estrecha o qué tan ancha debe crecer cada pista. Aquí, he especificado que la última columna puede no ser más pequeña que 24em pero puede flexionarse tan ancha como el espacio lo permita:

grid-template-columns: 1fr 1fr 1fr minmax(24em 1fr);

auto-fill y auto-fit

Cuando introduje valores de tamaño de pista, vimos la función repeat() para especificar patrones repetitivos de tamaños de pista. En este ejemplo, la función repeat() se usa para crear exactamente seis columnas repitiendo anchos de pista de 20em y 40em tres veces:

grid-template-columns: repeat(3, 20em 40em);

Otra forma de usar repeat() es especificar un tamaño de pista y dejar que el navegador calcule cuántas pistas repetir basándose en el espacio disponible. Esto se hace usando el valor auto-fit o auto-fill en lugar de un entero de conteo de repetición (3 en el ejemplo anterior). Estos valores son geniales para grids implícitas donde quieres aprovechar la alineación vertical y horizontal de una grid, pero no estás atado a un número particular de columnas.

Veamos cómo funciona esto usando nuestro ejemplo simple de cinco elementos de anteriormente en el capítulo. Sé que me gustaría que cada columna tenga 200 píxeles de ancho, pero no sé cuántas columnas cabrán cuando llegue al dispositivo del usuario. El valor auto-fit le dice al navegador “haz tantas pistas como quepan hasta que todos los elementos estén colocados”. El valor después de la coma establece el ancho de pista:

grid-template-columns: repeat(auto-fit, 200px);

La FIGURA 13 muestra el resultado cuando la grid se muestra en ventanas de navegador anchas y estrechas. Nota que en la ventana ancha, la grid tiene cinco columnas de ancho con espacio extra a la derecha; esto es porque solo hay cinco elementos, y auto-fit deja de hacer pistas cuando se queda sin elementos.

El valor auto-fill funciona de manera similar, excepto que crea tantas pistas como quepan, independientemente del número de elementos. En la FIGURA 14, el Inspector de Grid revela que la grid auto-fill tiene siete columnas, con dos celdas vacías. Es una diferencia sutil, y aunque auto-fit se usa más comúnmente, ambos tienen sus usos.

ADVERTENCIA
Las palabras clave basadas en contenido (auto, min-content, y max-content) no pueden usarse con auto-fill o auto-fit.

Vale la pena notar que puedes usar auto-fit y auto-fill para crear pistas de fila basándose en la altura disponible de la grid también; sin embargo, en el contexto del diseño web responsivo, el ancho es generalmente la dimensión restrictiva.

Solo he arañado la superficie de trabajar con auto-fit y auto-fill aquí. Para una explicación más profunda, recomiendo el artículo "Auto-Sizing Columns in CSS Grid: auto-fill vs auto-fit" por Sara Soueidan en CSS-Tricks (oreil.ly/NkaOb).

Media Queries

El enfoque auto-fit/auto-fill funciona genial para grids implícitas, pero si estás usando una grid explícita para diseñar componentes de página deliberadamente, puede que no sea el comportamiento que quieres. Para casos cuando necesitas una estructura de grid completamente diferente en pantallas pequeñas, medianas y grandes, la solución es entregar una grid apropiada con una media query. Una media query verifica aspectos del entorno de visualización (como el ancho del viewport) y sirve un conjunto de estilos solo cuando se cumple un requisito especificado. Por ejemplo, si el navegador detecta que el viewport tiene solo 600 píxeles de ancho, tomará los estilos para la grid que diseñaste para funcionar mejor en ese tamaño.

Eso es todo lo que voy a decir sobre media queries ahora mismo, porque las cubriré en profundidad en el siguiente capítulo. Por ahora, ten en cuenta que es posible crear algunos diseños de grid diferentes dirigidos a varios anchos de dispositivo y hacer que lleguen a los usuarios correctos. Puedes combinar este enfoque con valores que dan flexibilidad a las grids para los tamaños intermedios también. Por ejemplo, puedes usar unidades fr o valores minmax() para asegurarte de que dos columnas llenen la pantalla en una variedad de tablets, pero cambiar a un diseño de tres grids cuando la página se ve en un monitor de escritorio grande.
